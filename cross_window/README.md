# Temporal-window response-safety replay (R73)

This is a descriptive trace-driven, model-based test of whether the R56
response-safety/coverage pattern persists across six different GeoLife weeks.
The data-source restriction and the economic-model boundary are unchanged:
GeoLife contributes provider presence and position; requests, capacities,
costs, responses, contracts, and payments are generated by the model. The
weeks are distinct, but some people may occur in multiple weeks. The three
seeds per week change modeled inputs, not the observed mobility series.

`preregistration.json` fixes the exact dates, seeds, stress patterns, and
comparison before formal outcomes. The imprecise month-selection wording and
a blocked draft smoke test are documented in `deviation_log.md`; no formal
outcome was used to replace a window or select a bound. The completed run
retained all 108 cells. The source and runner hashes are in
`results/completion.json`.

## Rebuild and replay

Acquire GeoLife GPS Trajectories 1.3 through the data owner's authorized
process and extract its `Data` directory. In a clean clone, install the
environment in `../legacy/response_safety/current/code/requirements-win-py314-lock.txt`.
The following commands write only to an external, restricted directory. Use
a new output directory; they never download or redistribute GeoLife.

```powershell
python -B cross_window/run_cross_window.py prepare --raw "C:\path\to\Geolife Trajectories 1.3\Data" --out "C:\restricted\pasi-r73"
python -B cross_window/run_cross_window.py check --out "C:\restricted\pasi-r73"
python -B cross_window/run_cross_window.py smoke --out "C:\restricted\pasi-r73"
python -B cross_window/run_cross_window.py run --out "C:\restricted\pasi-r73"
python -B cross_window/run_cross_window.py summarize --out "C:\restricted\pasi-r73"
```

The published `results/seed_results.csv`, `window_summary.csv`, and
`window_paired.csv` are aggregate outcomes only; no coordinates, IDs, raw
events, or per-provider/task/slot logs are published. The `redistributable`
field in seed rows describes the restricted GeoLife source, not the aggregate
CSV itself. The externally generated cache and episodes must never be
committed or uploaded.

## Outcome and boundary

There were 108 completed simulation cells and no execution exceptions. In
the 18 down-step point-profile cells, 4,217 of 22,819 assigned services
violated QoS (18.480% pooled) and one IR violation was observed; all 18
point-profile down-step simulator statuses were `failed`. In the 18 up-step
point-profile cells there were 11,884 target misses and 4,417 slots where
settlement exceeded the point reserve; their simulator statuses were also
`failed`. No profile exceeded the actual available budget. Across all 54
fixed-envelope cells, no QoS, IR, or target violation was observed under the
declared response interval, but this is **not** a population risk certificate.

For the down-step condition, the fixed envelope lowered mean assignment
coverage by 24.323--26.469 percentage points across the six weeks (mean
25.410 points) relative to the frozen point. Qualified coverage was also
lower by 9.364--12.898 points (mean 10.848 points), even though the point
profile suffered QoS violations. These are window-level descriptive values,
with three modeled seeds averaged inside each week. The results support a
conditional safety--coverage trade-off; they do not establish a 0.5% chance
constraint, real payment responses, or independence of participant cohorts.
